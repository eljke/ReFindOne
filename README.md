# ReFind One

Личная библиотека ссылок, заметок, скриншотов и документов для iPhone. Русский интерфейс, локальное хранение, поиск и распознавание текста без сервера. Работает на iOS 17+; основной сценарий установки — гостевая IPA в LiveContainer.

Текущая тестовая версия указана в [VERSION](VERSION). Изменения — в [CHANGELOG.md](CHANGELOG.md). Готовые IPA доступны в [Releases](https://github.com/eljke/ReFindOne/releases).

## Начать пользоваться

1. Сохрани ссылку, текст, фото или документ кнопками в библиотеке. Название необязательно.
2. Новые материалы появятся во «Входящих». Поиск учитывает название, заметку, теги и распознанный текст. Можно вводить начало слова: «помид» найдёт «помидоры».
3. Свайп вправо добавляет в избранное. Свайп влево открывает архивирование и удаление. Долгое нажатие открывает те же действия.
4. Во «Всё» видны и архивные материалы. «Избранное» тоже включает архив. Тип материала и текст поиска сочетаются с выбранной коллекцией.
5. Открой карточку для редактирования, копирования текста, открытия источника или просмотра вложения. Фото и PDF открываются нажатием на вложение.
6. В настройках экспортируй коллекцию вместе с вложениями. Перед обновлением приложения обязательно сохрани копию.

## Сохранить через «Поделиться»

В LiveContainer 3.8+ с установленным Share Extension: Safari или «Файлы» → «Поделиться» → LiveContainer → ReFind One. Ссылка открывается в форме для проверки и сохранения; поддерживаемый файл импортируется во входящие.

Используется расширение самого LiveContainer, отдельный пункт ReFind One на верхнем уровне системного меню не регистрируется. Если LiveContainer отсутствует в списке, проверь «Ещё» и наличие его Share Extension при установке. Передача из «Фото» или выделенного текста зависит от формата, который отдаёт исходное приложение: LiveContainer 3.8 обрабатывает URL-провайдеры. Для неподдерживаемых вариантов остаются выбор фото и ручная вставка.

Если из Яндекс Маркета или другого приложения ReFind One открывается без формы, а из Safari передача работает, используй обходной путь: в исходном приложении нажми «Поделиться» → «Копировать ссылку», открой ReFind One → «Из буфера», проверь адрес и нажми «Сохранить». Если скопировались название товара и адрес вместе, оставь в поле только HTTP/HTTPS-адрес, чтобы сохранить именно ссылку. Обычный текст сохраняется как заметка. Формат передачи Маркета на конкретном устройстве пока не подтверждён; в [коде расширения LiveContainer](https://github.com/LiveContainer/LiveContainer/blob/main/ShareExtension/ShareModels.swift) обработка ограничена URL-провайдерами. При отсутствии такого провайдера приложение может запуститься без материала; гостевая IPA не может восстановить непереданные данные.

Приложение принимает web activities, HTTP/HTTPS и файловые URL. Дополнительно поддерживается `refindone://capture?text=<URL-encoded text>`; в LiveContainer такой URL нужно передавать гостю через его механизм открытия ссылок. Прямую системную регистрацию гостевой схемы LiveContainer не обеспечивает.

Библиотека загружается порциями по 60 записей. Кнопка «Показать ещё» открывает следующую порцию. Сортировка — от новых к старым или наоборот.

## Установка и обновления

1. На iPhone открой [Releases](https://github.com/eljke/ReFindOne/releases) под своим GitHub-аккаунтом.
2. Скачай файл `.ipa` из нужного релиза. Для файла из Actions сначала распакуй внешний ZIP.
3. В LiveContainer нажми «+» и выбери IPA. Для обновления выбери замену существующего ReFind One.
4. Сохраняй тот же контейнер данных. Не удаляй приложение перед обычным обновлением.

LiveContainer должен быть установлен и настроен для JIT-Less signing. Официальная [диагностика подписи](https://livecontainer.github.io/docs/faq/jit-less-mode-setup). AltStore обслуживает подпись LiveContainer; ReFind One импортируется в сам LiveContainer.

При первом переходе с 0.2 база автоматически обновляется до схемы v2. JSON-копии v1 поддерживаются. Приложение 0.2 не открывает базу v2: для отката нужен отдельный контейнер и импорт копии.

## Возможности и ограничения

- HTTP/HTTPS-ссылки очищаются от известных tracking-параметров; повторные нормализованные ссылки не создаются.
- Поддерживаются JPEG, PNG, HEIC/HEIF, PDF и UTF-8 TXT, до 20 МБ на файл.
- Изображения распознаются через Apple Vision. Из PDF извлекается текстовый слой; OCR сканированных страниц пока отсутствует.
- SQLite WAL и FTS5; при отсутствии FTS5 используется LIKE. Транзакции синхронизируют записи и поисковый индекс.
- Копия — JSON v1 с Base64-вложениями, до 250 МБ. Импорт добавляет отсутствующие UUID и не заменяет существующие записи.
- Архив проверяется целиком, затем файлы подготавливаются и записи добавляются одной транзакцией. При обычной ошибке новые файлы очищаются. Обрыв процесса может оставить неиспользуемые файлы.
- JSON-копия целиком обрабатывается в памяти и не зашифрована.
- Нет аккаунтов, сетевых SDK, JIT, собственного системного расширения или фонового наблюдения за буфером обмена.
- Гостевые приложения в LiveContainer не полностью изолированы друг от друга. Приложение не предназначено для хранения секретов.

## Разработка на Windows

Git и GitHub CLI позволяют отправлять исходники; Xcode работает в GitHub Actions. Локальная macOS не нужна. Подробности — [WINDOWS11_BUILD.md](WINDOWS11_BUILD.md).

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\publish_windows.ps1
```

Скрипт использует Conventional Commit `chore: update ReFind One sources`. Предпочтительно коммитить законченные изменения отдельно, с типом `feat`, `fix`, `test`, `docs`, `ci` или `chore`.

После добавления Swift-файлов или изменения версии пересоздай проект:

```powershell
python tools/generate_xcodeproj.py
```

## Проверки

```bash
swift test -j 2 -Xswiftc -strict-concurrency=complete
```

Переносимое ядро использует те же Swift-файлы, что и iOS-приложение. В GitHub Actions проверяются Linux-тесты, iPhoneOS-сборка и UI-сценарий на симуляторе iPhone 18 Pro Max. UI-сценарий сохраняет скриншоты в артефакт `ReFindOne-interface`.

Симулятор не проверяет запуск в LiveContainer, подпись, поведение системных пикеров и качество OCR на реальном устройстве. Проверки устройства — в [docs/RELEASE_CHECKLIST.md](docs/RELEASE_CHECKLIST.md).

## Версионирование и выпуск

- SemVer находится в `VERSION`; номер сборки — в генераторе Xcode-проекта.
- Разработка серии ведётся в `release/MAJOR.MINOR.PATCH`. Исправления и новые функции оформляются Conventional Commits.
- Тег `v<VERSION>` запускает тесты, собирает unsigned IPA, публикует GitHub Release с контрольной суммой и OCI-пакет `ghcr.io/eljke/refindone:<VERSION>`.
- Версии с суффиксом `-beta.N` публикуются как prerelease. Опубликованные теги и пакеты не перезаписываются.
- После успешного выпуска релизная ветка вливается в `main`, и `main` отправляется на GitHub. Тег сохраняет точный коммит сборки.

Для установки на телефон используй IPA из Releases. OCI-пакет содержит ту же IPA и контрольную сумму для воспроизводимого хранения и автоматизированной доставки.

Архитектура и инварианты описаны в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
