# Архитектура ReFind One

Приложение на SwiftUI, iOS 17+, без сторонних runtime-зависимостей и сетевого backend. Основная установка — гостевая IPA в LiveContainer. Данные пользователя остаются в активном контейнере приложения.

## Слои

- `Domain`: CaptureItem, типы материалов, коллекции, сортировка, правила URL и фрагменты результатов.
- `Data`: асинхронный CaptureRepository, SQLiteRepository actor, AttachmentStore actor, AppPaths.
- `Services`: локальный OCR через Vision, импорт файлов, BackupService actor, кэш уменьшенных изображений.
- `Presentation`: AppModel на MainActor; состояние интерфейса, фильтры и команды.
- `Views`: библиотека, форма добавления, карточка и настройки. Системный Quick Look показывает вложения.
- `App`: сборка зависимостей и общий интерфейс состояния.

## Хранилище

Путь базы: Application Support/ReFindOne/library.sqlite. Вложения: Attachments/<UUID>.<ext>. Генерируемые имена не зависят от внешних путей. Разрешены jpg, png, heic, pdf.

SQLiteDatabase принадлежит SQLiteRepository actor. WAL, busy timeout, параметризованные запросы. Изменение записи и FTS-индекса выполняется в одной транзакции. Обновление отдельных полей читает актуальную запись внутри транзакции, поэтому редактирование не откатывает избранное или архив и не воскрешает удалённую запись.

Схема v2 добавляет nullable `archived_at`. Миграция v1 → v2 сохраняет записи, перестраивает FTS и обновляет user_version в одной транзакции. Откат приложения 0.2 на базе v2 не поддерживается.

Коллекции:
- Входящие: archived_at IS NULL.
- Архив: archived_at IS NOT NULL.
- Избранное: is_favorite = 1, включая архив.
- Всё: без ограничения архива.

Тип материала и текст поиска применяются ко всем коллекциям. FTS-токены заключены в кавычки, экранированы и используют prefix search. До 8 токенов по 80 символов. При отсутствии FTS5 — LIKE с экранированием. Сортировка по created_at и id даёт стабильный порядок при одинаковых датах. Страницы по 60 записей, одна дополнительная строка определяет наличие следующей страницы.

Offset-пагинация сбрасывается при смене фильтров и перечитывается после локальных изменений. Параллельное изменение базы другим процессом между страницами не является поддерживаемым сценарием.

## Конкурентность и интерфейс

AppModel разрешает одну изменяющую операцию одновременно. Вложенные шаги импорта не сбрасывают isBusy. Поколение запроса и сигнатура фильтров предотвращают применение устаревших результатов. Поиск имеет задержку 180 мс.

Vision, PDF/файловый ввод, кодирование копий и уменьшение изображений выполняются вне MainActor. Превью создаются через ImageIO до 700 пикселей; NSCache ограничен 24 МБ. Полный файл открывается системным просмотрщиком. PhotosPicker может сначала загрузить выбранный оригинал в память; лимит проверяется до распознавания.

## Резервные копии

Формат JSON `refind-one`, version=1, ISO-8601 даты, Base64-вложения. Optional archivedAt сохраняет совместимость с архивами приложения 0.2. Экспорт ограничен 250 МБ, одно вложение — 20 МБ, до 20 000 записей.

Восстановление:
1. Декодировать и проверить весь архив: формат, версию, уникальность UUID, соответствие метаданных вложения его содержимому, имена, расширения и размеры.
2. Подготовить вложения с новыми UUID-именами для отсутствующих записей.
3. В одной SQLite-транзакции добавить отсутствующие UUID вместе с FTS.
4. Удалить подготовленные файлы, которые не использованы, либо все новые файлы при ошибке.

Существующие UUID остаются без изменений. Нормализованные URL не являются ключом восстановления: разные UUID из архива сохраняются. Автоматическая очистка рассчитана на обычные ошибки; аварийное завершение между записью файлов и коммитом может оставить неиспользуемые вложения. Потоковый формат, шифрование и восстановление после обрыва остаются дальнейшими задачами. JSON полностью находится в памяти.

## Входящие материалы

Share Extension принадлежит LiveContainer 3.8+, а не гостевой IPA. ReFind One использует публичные SwiftUI onOpenURL и onContinueUserActivity(NSUserActivityTypeBrowsingWeb). URL проходит SharedCapture.parse: HTTP/HTTPS становится черновиком, file URL идёт в штатный импорт с контролем доступа, расширения и размера. refindone://capture?text= принимает одну непустую строку до 200 000 символов. Данные не открываются в браузере и не скачиваются автоматически.

Входящие события ожидают завершения текущей операции или закрытия черновика в очереди MainActor. Ссылка сохраняется только после подтверждения. Очередь живёт в памяти: незавершённые запросы не восстанавливаются после принудительного завершения процесса.

Контракт сверялся с LiveContainer 3.8.0: ShareExtension/ShareModels.swift, ShareExtension/ShareExtensionViewModel.swift и TweakLoader/UIKit+GuestHooks.m в официальном репозитории. Текст и изображения без URL-провайдера это расширение не передаёт; отдельная Share Extension внутри гостя не регистрируется в iOS.

## Версионирование и доставка

VERSION задаёт SemVer. Генератор Xcode-проекта переносит числовую часть в MARKETING_VERSION, полную версию — в ReFindReleaseVersion. Bundle ID сохраняется: dev.refind.one.

Ручной workflow проверяет ядро, iPhoneOS-сборку и UI-сценарий на симуляторе. Теги v* дополнительно публикуют GitHub Release и приватный OCI-пакет в GHCR через GITHUB_TOKEN. Пакет скачивается обратно, и SHA-256 проверяется до публикации релиза. После выпуска main синхронизируется с релизной веткой. Сертификаты и Apple ID не используются в CI.

Проверки подписи, LiveContainer, OCR и системных пикеров на физическом устройстве остаются отдельным этапом.
