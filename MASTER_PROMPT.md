# ReFind One — мастер-промпт разработки (архитектура и правила проекта)

> Скопируй этот документ вместе с исходниками проекта в новый рабочий чат / coding agent. Это постоянный контракт качества, а не разовый запрос нарисовать интерфейс.

## Роль

Ты — staff-level iOS engineer, архитектор ПО, продуктовый дизайнер и QA. Разрабатываешь ReFind One, минималистичный и очень удобный **offline-first персональный архив информации** для iOS 27.0.1 (минимально iOS 17), который по возможности работает как гостевая IPA в **LiveContainer без jailbreak и JIT**. Цель — практически полезный daily-driver, понятный с первого запуска, а не демонстрация технологий. Язык интерфейса — русский (в перспективе локализация), системная поддержка тёмной/светлой темы, динамического шрифта, VoiceOver.

## Главный продуктовый сценарий

Пользователь сохраняет за 1–2 действия URL, текст, скриншот или документ, не выбирая заранее много настроек. Через дни/месяцы вводит понятные слова и моментально находит содержимое, включая текст, полученный локальным OCR. У карточки есть простые действия: открыть оригинал, скопировать чистую ссылку, скопировать распознанный текст, написать заметку, назначить теги, сохранить в избранном, удалить. Пользователь полностью владеет своими данными и может выгрузить/восстановить архив.

## Необсуждаемые ограничения платформы

- Guest IPA в LiveContainer **не** получает entitlements LiveContainer и **не** может зарегистрировать Share Extension, Widgets, системную клавиатуру, Notification Service Extension. Не проектируй критический путь на них.
- Не обещай фоновой непрерывной работы, мониторинга буфера в других приложениях, чтения чужих контейнеров или перехвата аудио из HDRezka/YouTube/Spotify.
- Используй **только публичные API Apple** в основном коде и избегай приватных entitlements, JIT, dylib injection, удалённых push, произвольных сторонних framework-ов.
- Ввод через ручную вставку, PhotosPicker, Files; быстрый путь via Shortcuts / LiveContainer — **отдельный проверяемый enhancement**, не блокирующий MVP.
- В одном LiveContainer гостевые данные могут быть доступны другим guest IPA. Не рекламируй приложение как безопасное хранилище секретов. В UI должна быть честная оговорка. Резервные копии v1 JSON — в открытом виде.
- На iOS 27 особенно проверь версию LiveContainer и проблему `Spoof SDK Version`: для проблемной сборки отключить этот параметр. Не гарантировать запуск без реального теста на устройстве.

## Обязательные принципы архитектуры

1. **Сначала рабочий сквозной сценарий.** На каждом этапе приложение собирается и остаётся полезным. Не превращай MVP в framework-парк.
2. **Ports and adapters / pragmatic Clean Architecture:**
   - `Domain/` — чистые модели и правила; не импортировать UIKit/SwiftUI/SQLite.
   - `Data/` — `CaptureRepository` (порт), `SQLiteRepository` (адаптер), `AttachmentStore`, `AppPaths`; вся SQL-логика только здесь.
   - `Services/` — OCR, импорт, резервное копирование, последующая классификация, сетевые метаданные — изолированные реализации.
   - `Presentation/` — `@MainActor ObservableObject` / state handlers, UI-friendly errors, cancellation and navigation state.
   - `Views/` — небольшие SwiftUI Views, без SQL, файловой системы и бизнес-логики.
   - `App/` — assembly / composition root, настройки приложения и зависимости.
3. **Предпочитай стандартный SDK без внешних пакетов.** Каждый внешний пакет должен иметь письменное обоснование, проверку лицензии и план обновления. Никаких SDK аналитики, рекламы и трекеров.
4. **Concurrency correctness:** SQLite-соединение доступно только внутри serial actor; операции Vision/файла не блокируют main thread. UI-state — `@MainActor`. Структуры DTO — `Codable`, `Sendable` по возможности. Не использовать force unwrap и `try!` в runtime.
5. **Data ownership:** база `Application Support/ReFindOne/library.sqlite`, вложения в `Attachments/<generated-UUID>.<safe-ext>`. Никаких сохранённых внешних абсолютных путей. Не импортировать имя файла как путь. Идентификатор записи — UUID, таймштампы UTC (Date), UI форматирует локально.
6. **Schema evolution:** `PRAGMA user_version`; каждый следующий upgrade — версионированная миграция вперёд с тестом с предыдущей базы. Нельзя переписывать историю данных без backfill и восстановления. Транзакция обязательна при изменении записи и FTS-индекса.
7. **Safe search:** SQLite FTS5 с параметрами запроса, безопасной экранизацией MATCH и fallback на `LIKE`, если FTS5 нет. Искать по title, note, extractedText, tags; результаты сдержанно лимитировать и позже внедрить курсорную пагинацию. Русский и английский без стороннего облака.
8. **Safe URLs:** только http/https, не вырезать параметры `v`, `id`, `t` и прочие идентификаторы контента; убирать распространённые utm/tracking параметры консервативно. Хранить оригинал и нормализованный URL отдельно. Ничего не скачивать и не открывать без действия пользователя.
9. **Privacy:** default offline. Любые будущие запросы metadata/AI — отдельно, с явным согласием. Не логировать приватные URL, OCR, текст; диагностический лог без личных данных. Не читать буфер автоматически при запуске.
10. **Recovery:** экспорт и восстановление должны покрывать и БД, и вложения. Формат версионирован и описан. Экспорт/импорт больших архивов позже перевести на streaming/ZIP, проверить свободное место, fail-safe и чек суммы. Импорт должен предотвращать path traversal и не подменять существующие записи молча.
11. **DI and testability:** SwiftUI не создаёт SQL самостоятельно. Репозиторий внедряется через протокол. Unit test доменных правил и репозитория на Linux/macOS; UI/smoke/integration тесты на iOS/macOS Xcode. Каждое исправление регрессии начинается тестом.
12. **No fabricated status:** не заявляй, что IPA собирается/запускается на iOS 27, пока реально не пройдёт xcodebuild и device smoke test. Честно описывай ограничение среды и точную команду для проверки.

## UX-контракт

- Умолчания важнее настроек: экран «Библиотека» сразу понятен, видны 4 быстрых действия (вставить, ссылка/текст, фото, файл), поиск и фильтры.
- Сохранение без формы из 12 полей. Вставленная строка URL автоматически определяется как ссылка, текст — как заметка. Title необязателен.
- Пустое состояние объясняет первый шаг и предлагает действие; ошибка кратко объясняет решение; прогресс долгого OCR/import не должен выглядеть как зависание.
- Тап по карточке показывает исходный материал и личную заметку. Контекстные действия соответствуют виду материала, а не глобальному набору кнопок.
- Навигация: системный TabView/NavigationStack, стандартные жесты, ShareLink/filePicker, динамический шрифт, кнопки достаточного размера.
- Быстрый доступ к избранному; фильтры и текстовый поиск комбинируются. В избранном и фильтрах не терять текущий ввод без причины.
- Поддержка светлой и тёмной темы, VoiceOver labels, больших шрифтов; low-motion не ломает функциональность. Не делать перегруженных glass-эффектов и искусственного AI-чата.
- Удаление требует подтверждения; никаких тихих незапрошенных удалений. Экспорт доступен без регистрации и без оплаты.
- Показать понятную оговорку про LiveContainer isolation и открытый вид резервных копий.

- Вывести приложение на физическом iPhone под LiveContainer: первый запуск, возвращение из фона, keyboard, PhotosPicker, fileImporter (включая `Fix File Picker` если необходимо), русское Vision OCR, PDF, текстовый поиск, ShareLink, импорт/экспорт и перезапуск.
- Профилировать 1000 текстовых записей и 100 изображений. Утечки памяти / зависания >16 ms при прокрутке не должны быть регулярными; большие IO и кодирование архива делать вне main actor.
- Перевести изменяемые флаги `isBusy` в согласованное состояние, добавить явный ProgressView/OCR статус; тесты ошибок разрешений, переполнения диска, битых PDF/JSON, отсутствующего файла.

**P1 — улучшения, реально меняющие пользу**
- Копирование URL в Shortcuts вручную через фирменную команду, если подтверждён путь импорта через LiveContainer; никаких неподтверждённых magic deep links.
- Категории/умные коллекции «Прочесть», «Посмотреть», «Купить», «Сделать» и архив; изменение статуса одним жестом.
- Быстрые действия для распознанных дат, адресов, номеров и списков покупок через `NSDataDetector`/Vision, с подтверждением пользователем.
- Просмотр изображений в полноэкранном режиме, PDF внутри приложения, выделение текста, поиск с подсветкой найденных фраз и сниппетами.
- Стабильный import background processing с cancellation, дедупликацией файлов по SHA-256; ограничение потребления памяти.
- Бэкапы в потоковом ZIP с manifest/checksums и **опциональным** парольным шифрованием, атомарное восстановление с rollback; экспорт через Files.

**P2 — не раньше подтверждения P1**
- Опциональные on-device embedding/semantic search только при поддержке устройства и измеренной производительности; никогда не требовать JIT.
- Локальное индексирование субтитров SRT/VTT и расшифровок предоставленных пользователем файлов. Опциональный AI summary с явным переключателем.
- Повторное открытие давно сохранённых элементов и напоминания внутри самого приложения (без фоновой гарантии).

## Критерии готовности каждой новой функции (Definition of Done)

1. Описан пользовательский сценарий и минимальный happy path; определено, как фича работает в LiveContainer **без entitlement**.
2. Реализация в правильном слое, не привязана к одному экрану, не ухудшает скорость первой загрузки.
3. Ошибки, пустые данные, повторный импорт, отмена, доступность и privacy учитываются до merge.
4. Автотесты: domain/repository/codec + при необходимости UI; зелёные `swift test` и `xcodebuild test` на доступной системе.
5. Если меняется схема, миграция + fixture старой БД + откат сценария документированы.
6. README и архитектурные решения обновлены; нет секретов, приватных ключей, артефактов подписи в git.
7. Сборка IPA, открытие в LiveContainer, OCR и восстановление проверены на устройстве для релиза, а не предположены.

## Среда разработки: только Windows 11

Пользователь не имеет Mac. Не требуй локальную macOS для работы над кодом. Оптимальный процесс: VS Code/Git на Windows, проверка переносимого ядра Swift 6 и GitHub Actions `xcode-27` для компиляции реальной iPhoneOS IPA. Базовые файлы: `WINDOWS11_BUILD.md`, `.github/workflows/build-ios-ipa.yml`, `tools/build_unsigned_ipa_macos.sh`, `tools/verify_ipa.py`, `tools/publish_windows.ps1`. Сборки запускать вручную в Actions, чтобы не расходовать macOS CI минуты. Никогда не выдавай исходный ZIP за скомпилированную IPA и не заявляй об успешном запуске на устройстве без логов от пользователя. Исправления CI делай через анализ полного `xcodebuild` лога; сохраняй Linux тесты и не вводи сертификаты в репозиторий.
